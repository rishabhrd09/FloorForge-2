# FloorForge Compass implementation prompt

Use the following prompt with the implementation agent in the target FloorForge checkout. Keep `docs/COMPASS_REFACTOR_PLAN.md` available with it.

---

Implement the Compass map and survey refactor specified in `docs/COMPASS_REFACTOR_PLAN.md`. The objective is a click-based planning experience for ordinary users: describe a home, confirm a short setup, place rooms on an oriented grid, refine selected cells, and generate consistent 2D/3D output from those choices. Read the complete specification before editing.

Inspect the actual repository and applicable `AGENTS.md` instructions first. This specification was prepared against the FloorForge workspace named `Design_aesthtic_3d_home`; if working in a different Floorforce 2 checkout, identify equivalent contracts and document material differences before implementing. Preserve the current stack and naming conventions.

The current fixed 4 × 4 Quick Guide is a dimensionless relative-position input. Its existing `spatial_hint` schema must keep that meaning. The existing eight-position room board introduces a passage and may align/swap stairs; those behaviours are not a faithful compiler for the richer Compass. Create a separate, validated, versioned Compass input and adapter into the existing Custom Plan geometry pipeline. Keep the legacy paths operational.

Implement these user-facing requirements:

1. Offer eight short foundation steps: main road side; plot frontage width; plot depth; plot context; occupied floors; bedroom requirements; gate side; grid detail. Put units/custom dimensions inside the dimension steps. Prefill from existing project/text inputs, preserve skipped answers, and keep Back/Continue/Save and exit predictable. Retain the existing baths, pooja, parking, kitchen, Vastu, budget and theme controls as accessible home preferences.
2. Keep the editor road/front at the bottom and back at the top. Use the existing eight bearings. Changing geographical bearing must not rotate or permute the working assignments. Preserve this orientation in 2D and furnished top views. Show real plot proportions, compass, scale, boundary labels, setbacks, gate, current room and progress.
3. Support 4 × 4, 4 × 6 and 4 × 8 base grids, aligned across every occupied floor. Keep logical row zero at the front while displaying the back row first. Show allocation span separately from clear room dimensions. Following the specification's FloorForge adaptation, the central room grid spans the buildable envelope, with clearly labelled plot/setback site bands around it.
4. Support room-first and cell-first placement. Use eight large room cards per page and a responsive layout. Stable room IDs distinguish same-type rooms. Joining regions of the same ID creates one room; diagonal contact does not connect it. Replacement, erase, movement and enlargement must check donor/recipient connectivity and preserve required-room records when they become unplaced.
5. Refine through an enlarged view of exactly two equal left/right halves. Keep a divided overview cell one target. Opening/cancelling must not mutate input. Division plus assignment is one undoable transaction; existing ownership initially extends to both halves. Whole cell asks who retains it if owners differ. Show a miniature map, floor/row/column, dimensions, warnings, rooms below, Undo and Back. Disable background actions while focused editing is active.
6. Add conditional questions with large cards and explicit model consumers. Cover relevant room programme, enclosure, attached bathrooms, stairs/landings, access, upper outdoors/voids, target sizes and preferences. Never ask the user to fill sixteen slot questions and then repeat those placements on the map. Resolve map/text conflicts through a small, visible choice. Every retained answer must show applied/preference checked/needs clarification/note only accurately.
7. Preserve Ground, First, Second, existing roof terrace access and advanced exact editing. Roof access is separate from occupied-floor count. Show below-floor information and validate linked stairs, landings, support, open-to-sky and void relationships. Do not reduce FloorForge to the reference application's two floors.
8. Provide normal Undo/Redo, autosave, portable project saving, recoverable migration, useful loading/error/retry states, and keyboard/touch/mouse operation without mandatory dragging, hover or gaze READY. Remapping an occupied grid, clearing content and replacing an authored plan need a concrete preview/confirmation. Retain drafts when inputs are inactive.
9. Before generation, offer a valid consecutive floor scope such as Ground only without deleting upper drafts. Derive the scoped floor/bedroom counts, stairs and roof eligibility in temporary input, include the scope in build identity, and label partial results. Provide Back to map, floor switching, 2D/furnished-top/exterior views, notes and retry through existing viewer APIs. Keep existing walkthrough, PNG/PDF/DXF/GLB/IFC/package outputs consistent with the same accepted geometry and scope.
